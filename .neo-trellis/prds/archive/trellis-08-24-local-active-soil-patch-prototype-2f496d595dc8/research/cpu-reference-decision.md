# CPU reference decision

The bounded CPU representative path is the selected prototype and fallback.
It keeps one inspectable fixed-step implementation for low, balanced, and high
quality, with fixed representative, neighbor, substep, settlement, memory, and
time budgets. The task-local benchmark covers repeated cut injection, floor
flow/pile settlement, inner-shell containment, all four material presets, and
full flush conservation.

A `RenderingDevice` compute path is intentionally deferred. It would add a
second authority-adjacent implementation and readback/cleanup complexity without
solving a measured budget miss. Reconsider compute only after representative
visual density is deliberately raised and the same aggregate-volume interface
can remain unchanged.

Subjective appearance is not an automated acceptance gate for this task. The
presenter exposes live representatives for a later batched human visual review;
code validation owns conservation, authority isolation, lifecycle, and budgets.
