## 用户目标

破坏表现勉强可用，重点继续保障切削。倾倒主要承担可信的视觉反馈：挖掘时不能沿途遗留土块，卸土时应形成连贯、自然扩底的土堆。重新考虑表示方法，不继续默认通过调阈值、调颗粒数量解决。

## 已核实的代码问题

1. `godot/client/scripts/soil_effects.gd:618` 的 `_update_visual_mound` 为每次 accepted dump 分配持久池化球体；位置是 `dump_release_world + height offset`。它没有落地查询、寿命或向地面运动。`:349` 无条件从视觉快照调用它。
   `excavation_world.gd:665` 转发 release position；`voxel_excavation_authority.gd:1328` 的来源确实是 transaction.release_world，即铲斗开口。不是地面 support 的别名。Voxel 模式已有真实地面堆积，仍叠加这套遗留视觉土堆。这是可直接导致空中/路径残块的独立缺陷；尚无本次运行记录证明用户看到的每块土都来自它。
2. `voxel_excavation_authority.gd:1347` 只沿一个 xz 柱寻找最高支撑。`:820` 每批相对该支撑生成新的竖直 add shape；`:1712` 把它转成底粗顶细的两点路径。下一批命中上批堆顶，继续向上长，底座没有累计体积约束。半径还被限制到四个 voxel。
3. Native deposit 不进入旧 settle 路径。单批像圆丘不意味着多批的并集保持休止坡度。`tests/voxel_excavation_authority_test.gd:485` 的连续倾倒场景移动落点，不能排除固定落点成塔。
4. `soil_effects.gd:363` 把离散事件作为持续发射器：从冻结的旧开口发射 0.28–0.85 秒；`:491` 使用旧变换，`:524` 以 11 个/秒补发 clod，已生成 clod 最久保留 2.5 秒。冻结出生位置合理；持续在过去的位置新生土粒不合理。每次事件还 restart 粒子并清零 clod accumulator，可能使流动断续。
5. `voxel_excavation_authority.gd:1231` 只有朝向和 50 ms 门槛，没有“正在有效切削/出口埋土”的互斥准入。0.15 的开口点积意味着略向下就可能放行。它能解释部分真实释放，但不能据此断言所有漏土都源自角度。

## 建议的表示方法

| 阶段 | 表示 | 承担的职责 |
| --- | --- | --- |
| 未挖原土与切削 | 现有局部体素 SDF、扫掠切削 | 切口形状、占据、可重挖、碰撞 |
| 桶内 | 标量载荷与贴合桶腔的封闭网格 | 装载量、随桶运动的连续留土 |
| 空中 | 有限时长的落土流、少量弹道碎块、尘土 | 从实际出口到实际落点的运动线索 |
| 地面堆积 | 局部二维高度/体积目标，再写入同一 SDF | 扩底、并堆、回填、坡度与接触轮廓 |

局部二维规划只用于地面落料：每个 xz 柱规划表面增量，不接管整个场地，不复活旧 heightfield 挖掘后端。切削保留体素能力。权威与质量账本仍由现有 authority 持有；目标高度、特效和碰撞都不能各自拥有一份可独立增加的土。

不建议本轮引入 DEM/MPM/SPH 或整桶刚体颗粒。它们可以有更丰富的颗粒行为，但把桶壁碰撞、耦合稳定性和 GPU/native 集成也带进来，偏离当前视觉目标。纯装饰网格土堆是更便宜的另一端，但会牺牲当前可重挖与通行一致性；本建议保留这些能力。

## 堆积规划

- 从释放位置、初速度及重力近似计算落地区域，使用权威 SDF 查询而非可能滞后的 collider。沿出口宽度分布落料，不只用开口中心的一个点。
- 在落点周边的有限 patch 采样现有表面，保存 generation/revision。切削、压实、相邻倾倒后使相应缓存失效；重新采样当前 SDF，禁止用旧累计量恢复已挖走的土。
- 平地原型可使用锥形目标包络：`target(x,z) = max(current(x,z), peak - slope * distance)`，通过目标新增体积确定 peak。新增量为 `sum((target-current)*cell_area)`。重复倾倒提升同一包络并扩底，不在堆顶另起一个小丘。平地相似锥体的高度与半径均随累计体积的立方根增长。
- 通用坡地需要连通的落料传播、边界与障碍处理。不能直接把锥形包络投到隔墙另一侧或悬空支撑上。原型先覆盖平地、既有土堆、浅坑及简单斜面，再接复杂地形。
- 固定 patch 大小、求解次数、dirty-block 数和每次接收体积。预算不足则分批接收，剩余留桶；不能在半径上限内无限增加高度，也不能扣账后丢掉超额体积。
- 先在二维数组上求形状，再一次或少数几次发布到 SDF。执行器需做窄性能试验，比较有界 native 形状近似和局部 buffer 更新；不预先承诺任意高度场能由一个 `do_path` 精确表示。禁止重新采用每帧全三维积分/反复拟合。
- 不增加另一个永久可见 mesh 土堆。真实表面由同一 SDF 输出。若后续需要过渡表面，它只能是短寿命、同轮廓、随 revision 退休的表现层。

## 留土与落土生命周期

- 显式区分捕获、留存、释放、收尾。有效切削时优先捕获；出口埋土时不产生自由落体卸料。姿态阈值只是释放条件之一。
- 桶内网格只表达 retained amount。几何需用 SY135 桶腔验证，不能把“在一个代理盒子里”当作“在实际金属桶里”的充分证据。
- 每段已批准释放携带出生时间区间、起止出口变换、接受体积和落地区域。事件防重用于限制可发射的量；不能为每个事件自动追加一段完整的固定 TTL 新发射。
- 门关闭后停止新出生；已经在空中的土继续落到地面后淡出，不能瞬间消失，也不能继续从旧开口补生。
- 合并连续小事件时不 restart 整个粒子系统。发射量跟随批准释放量，连续性由小段插值提供；不是凭视觉帧数创造新的库存。
- 地面增长和飞行时间需协调。第一版可保留现有批提交与短增长滞后，但高位倾倒不得把远未落地的土立即表现为完整大堆。若需要准确到达时间，引入 authority 所有的有界 in-flight 预约，明确 reset、reject、cut 重叠和守恒处理，不能仅在 VFX 内延迟记账。

## 实施顺序与验收

1. 删除 voxel 路径的开口位置持久视觉土堆；回归验证 accepted dump 不生成空中静态残块。纠正旧测试把“无物理节点的假土堆存在”当作成功的要求。
2. 完成固定落点的二维堆积原型，测量重复十批/多桶的高度、占地、体积与批次划分敏感性。新增简单坡地与浅坑情形。之后再选择 SDF 发布执行器。
3. 接入单一 authority、材料账本、readiness、重挖缓存失效。守恒仍测，但必须独立测最终几何。
4. 替换固定旧位置 TTL 发射为连续有界释放段；接入切削/出口埋土抑制，覆盖带土切入、收斗、搬运、真正卸料、卸料后立即移动。
5. 只在相关代码稳定后跑窄 headless 回归和一次短性能测量。人工 Forward+ 验收固定位置连续倒土、平移倒土、上翻搬运与回挖，不用账本测试代替画面合格。

本轮为审计与方案收敛，未修改运行时代码，也未宣称解决了视觉缺陷。现有任务保留 in_progress。
