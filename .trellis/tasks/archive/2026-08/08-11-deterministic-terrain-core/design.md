# Technical Design

## Authority and state model

M4 adds a Godot-first local world profile alongside the legacy Python terrain
service. `TerrainState` is the only local terrain authority for this profile:

```text
seed/config -> baseline stable Float32 + loose Float32
ordered edit queue -> fixed-step reducer -> revision + surface snapshot
surface snapshot -> generation-gated TerrainRenderer -> ArrayMesh
```

Python remains authoritative for the excavator joints and input safety. The M4
terrain node does not send terrain heights, mesh vertices, or bucket state over
the motion WebSocket. Later M5 may consume authoritative frame transforms as
inputs to local bucket interaction, but the direction remains one-way.

## TerrainState contract

- Grid: default 41×41 cells, 0.5 m spacing, row-major indexing, world origin at
  the centered X/Z corner. The dimensions are constructor parameters bounded to
  2..201 and 50,000 cells.
- Baseline: a deterministic low-amplitude seeded heightfield generated by
  integer modular arithmetic in world-cell coordinates. No engine noise object
  or unordered container contributes to the result.
- Layers: `stable_heights` and `loose_depth`, both `PackedFloat32Array`; surface
  is recomputed as `stable + loose` after each fixed step. Cut edits consume
  loose first and clamp stable lowering to baseline minus 3 m. Positive edits
  add loose depth. M5 owns repose/bucket-volume semantics.
- Identity: `terrain_epoch` is deterministic for the seed/config, revision starts
  at zero, and `world_generation` advances on reset. Snapshot metadata includes
  algorithm version, seed, rows, columns, spacing, origin, revision, epoch and
  SHA-256 digest of row-major Float32 surface bytes.
- Queue: `enqueue_brush(sequence, center_xz, radius_m, delta_m)` accepts a finite
  positive radius and strictly increasing sequence. `step_fixed()` sorts and
  applies the queued commands in sequence order; invalid/stale commands are
  rejected before any array mutation.

## TerrainRenderer contract

`TerrainRenderer` is a `MeshInstance3D` derived-output owner. It copies the
surface snapshot when queued, stores `(world_generation, revision)`, and ignores
requests older than the latest queued/applied identity. `apply_pending()` builds
an indexed triangle `ArrayMesh` with vertices, UVs and deterministic normals.
Mesh creation failure is caught by the owning `TerrainWorld` and leaves the
previous mesh/state usable.

## Scene/test integration

`TerrainWorld` under `Main/TerrainRoot` owns `TerrainState` and wires a
`TerrainRenderer` child. It initializes the default seed on `_ready`, queues and
flushes the first mesh, and exposes test seams for deterministic edits/reset.
The existing `FoundationGround` remains as a fallback visual in case the mesh
is unavailable.

## Compatibility and rollback

The M4 code is entirely under `godot/client/`. Existing Python terrain routes,
protocol schemas and M2 motion scripts remain untouched. If mesh generation or
the local algorithm fails, disable `TerrainWorld` and the fallback ground still
renders the excavator scene. M5 can replace the brush reducer without changing
the seed/grid/snapshot or generation guard contracts.
