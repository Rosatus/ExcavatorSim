# Implementation plan

1. [x] Add a shared, snapshot-height-sampled, deterministic code-native site
       dressing layer outside both Terrain3D and fallback ownership.
2. [x] Establish work zones and scale cues with non-colliding barriers, stakes,
       route/track marks, signage, and stored construction materials.
3. [x] Upgrade fallback terrain to a procedural compacted/loose/damp/macro
       material while retaining accepted mesh topology and terrain authority.
4. [x] Extend low/balanced/high dressing, shadow, and atmosphere budgets and
       publish their applied status.
5. [x] Add deterministic non-screenshot contracts for composition, collision
       isolation, backend parity, reset/model invariance, and quality limits.
6. [x] Run focused terrain/visual/offline regression and one completion gate,
       update frontend boundary, commit, and archive. Defer subjective visual
       approval to final human product-experience validation.

## Risk and rollback

- Dressing is always disposable presentation and contains no CollisionObject3D.
- Terrain shader inputs are accepted mesh attributes only; they never become
  stable/loose classification or material inventory.
- Native/fallback visibility may change, but the shared dressing identity and
  deterministic placement may not.
