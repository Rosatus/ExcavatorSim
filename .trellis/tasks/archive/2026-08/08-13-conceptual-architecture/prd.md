# 编写概念架构文档

## Goal

面向非技术人员，用一页左右的简体中文 Markdown 说明 ExcavatorSim 的核心工作方式：人发出操作意图，Python 负责安全且确定地计算挖掘机运动，Godot 负责施工场景与拟真呈现，结果在桌面显示器上反馈。

## Requirements

- 交付 `docs/architecture/conceptual.md`，作为工程详细架构的前置阅读入口。
- 主图采用参考图的简洁构图思路，至少包含：操作人员、当前输入设备（键盘/通用手柄）、Python 运动与安全核心、Godot 场景/地形/挖掘机、桌面显示器。
- 同一主图提供 Mermaid 版本和 HTML/SVG-like 内嵌版本；两者节点、方向和状态必须一致。HTML 版不能成为唯一信息载体，图下要有纯 Markdown 摘要。
- 目标座舱手柄、踏板、按钮面板、中控触屏、CAN-to-USB/现场总线只以虚线和“未来规划/未接入”标签出现，不能与当前输入路径混在一条实线链路中。
- 用少量业务语言解释四件事：谁操作、谁计算运动、谁生成画面、用户在哪里看到结果；不要出现类名、线程名和完整字段清单。
- 统一状态图例：实线/实底=当前已实现；点划线/浅色=legacy 兼容；虚线/黄色=未来规划或无仓库证据。
- 页面注明事实截止日期 `2026-08-13`、当前 Godot-first 主路径、legacy 仅兼容，并链接 `engineering.md` 和 `README.md`。

## Acceptance Criteria

- [ ] 不看代码的读者能从首屏图文回答“谁操作、谁计算、谁显示”。
- [ ] Mermaid 与 HTML 图的组件集合、箭头方向、当前/legacy/未来状态一致。
- [ ] 图中没有把 CAN、中控、真实座舱或 MCP 写成已实现产品组件。
- [ ] 图下文字明确 Python→Godot 是运动状态/画面消费方向，Godot→Python 只有当前输入意图与生命周期命令，不回写视觉/地形权威。
- [ ] Markdown 在不渲染 Mermaid/HTML 时仍能通过表格/文本理解同一内容。
- [ ] 所有内部链接是仓库相对有效路径；无网络图片、外部图床或新运行时依赖。

## Out of Scope

- 工程类名、端口、JSON 字段、线程频率、坐标矩阵、测试命令的完整说明（由工程文档负责）。
- 真实硬件驱动、CAN 协议或座舱 UI 实现。
- 修改产品代码或运行时行为。
