# Earthworks construction-site worldbuilding

## Goal

在不干扰当前 ExcavatorSim 主程序开发和主 Godot 场景运行的前提下，从零搭建一套可独立打开、可独立预览、具备可信工程尺度与清晰作业动线的土方施工现场。场景使用 Terrain3D 承担不可挖硬地表，使用 Voxel Tools 1.7 的有限 VoxelTerrain 承担圈定的可挖土体，并以 `E:\projects\blender\construction` 中的 GLB 素材完成首轮重点布景。

## Background

- 当前 `godot/client` 编辑器正在运行产品主场景；把大型 GLB 直接放入该项目会触发扫描和导入，可能干扰另一位 agent。
- 项目锁定 Godot `4.7.2.stable.custom_build.ed1daf0bf` 与 Voxel Tools `1.7`，同时 vendored Terrain3D `1.0.2`。
- 外部施工素材库包含 44 个已转换 GLB，总量约 2.7 GiB；除植被外，常见道具通常约 100 万三角面，两个最大资产超过 500 万三角面。
- 用户明确要求本次地图从零构建，不继承现有场景的构图或施工区设计；减面与重拓扑延后，优先完成地编。

## Requirements

### R1. Development isolation

- 新地图必须位于仓库内独立的 Godot worldbuilding workbench 中，拥有独立的 `project.godot`、`.godot` 缓存、场景入口、地形数据与本地素材缓存。
- 不修改 `godot/client/project.godot` 的 `run/main_scene`，不修改或实例化 `godot/client/scenes/main.tscn`，不把新地图自动接入任何产品启动链路。
- 首轮 workbench 依赖和大型源素材不得触发当前 `godot/client` 编辑器扫描。

### R2. New map, not a retrofit

- 地图的地貌、路网、作业分区、灯光、构图与布景从空白场景开始设计。
- 现有产品场景只可作为引擎/插件版本事实的来源，不作为布局模板、地形数据源或视觉构图基础。

### R3. Terrain ownership

- Terrain3D 仅负责不可挖的外围硬地表、道路基底、场站和远近景起伏。
- 一个边界明确的有限 VoxelTerrain 仅负责可挖作业区；两套地形不得在同一平面上同时生成可见表面或碰撞。
- 可挖区必须有足够土层深度，不能在浅挖后露出 Terrain3D 硬地表；接缝必须通过网格对齐和场景设计获得干净、可信的视觉过渡。

### R4. Worksite composition

- 场景至少包含：主入口与安全管制、双向土方运输主路、设备集结/维护坪、核心开挖工作面、弃土/堆料区、管材与施工材料区、排水或临时沟渠、外围安全缓冲带。
- 路宽、转弯半径、坡度、工作面净空和设备回转空间应适配中型履带挖掘机与土方车辆，而不是只追求俯视构图。
- 出生/预览起点位于作业区外，动线应自然引导进入施工区，并提供至少一条不穿越核心挖掘面的安全环路。

### R5. Visual direction

- 首轮采用偏写实的 PBR 工地风格：土色、压实路面、混凝土、金属和安全橙形成清晰材质层级；整体以可读性和工程可信度优先。
- 使用温暖但中性的下午日光、轻量空气透视与受控尘雾，保证工作面轮廓、坡面和道路边界清楚，不依赖重度后处理掩盖地形问题。
- 场景需同时具备远景总览、中景动线和近景作业面三个阅读层次。

### R6. GLB use and source preservation

- 从外部素材库中只选择能形成视觉锚点的少量 GLB；重复护栏、标桩、道路边缘等高密度物件优先使用低成本模块化几何或代理，不批量散布百万面源资产。
- 被采用的 GLB 必须保持源字节不变，并记录源路径、大小、SHA-256、用途、场景尺度和导入状态。
- 首轮不得改写源 GLB，也不得把整个 2.7 GiB 素材库复制进仓库。
- 资产缺失时 workbench 应能以代理几何打开，而不是因丢失外部本地缓存而无法解析场景。

### R7. Reviewability

- 提供独立可运行的预览场景、自由观察相机，以及总览、入口、核心工作面三组固定审阅视角。
- 提供可见但可关闭的地图分区/尺寸诊断层，便于核对道路、Voxel 边界、Terrain3D region 和出生点。
- 场景结构、素材同步和人工验收步骤必须写入 workbench README。

### R8. Scope discipline

- 本阶段只完成场景、地形所有权、可游览性与视觉布景，不接入挖掘机控制、土量账本、产品 UI、Gateway、保存系统或发行包。
- 资产减面、LOD、纹理图集与最终产品迁移作为后续阶段；只有原始素材已经阻塞编辑器稳定性时，才允许临时替换为代理，不展开全面优化。

## Acceptance Criteria

- [ ] AC1: 运行 workbench bootstrap 后，可用锁定的自定义 Godot 独立打开地图；`godot/client` 当前主场景、入口文件和运行状态不需改变。
- [ ] AC2: 地图从外部入口到设备坪、工作面、弃土区和材料区具有连续、可信且适配工程车辆的通行路线；出生点不在可挖作业区内。
- [ ] AC3: Terrain3D 与 VoxelTerrain 的渲染和碰撞所有权互斥；边界无大面积缺地、明显穿插、z-fighting 或可踩到的双层地面。
- [ ] AC4: VoxelTerrain 可挖体积至少覆盖完整作业面并具有约 12 m 的有效土层深度；对其进行一次局部移除验证时不会露出隐藏的 Terrain3D 地表。
- [ ] AC5: 场景具备清楚的入口、环形运输主路、维护坪、开挖面、堆料区、管材区、排水构造与安全边界，且三个审阅尺度均有明确视觉焦点。
- [ ] AC6: 首轮采用的每个外部 GLB 都能追溯到 manifest，源/缓存 SHA 一致；最大两个超重资产不进入首轮，缺失本地 GLB 时代理仍可正常加载场景。
- [ ] AC7: 自动化检查能验证插件类可用、场景可解析、关键节点存在、Terrain/Voxel 边界契约成立，以及变更没有越出 workbench 与本 Trellis 任务目录。
- [ ] AC8: 一次最终 Forward+ 人工审阅确认地图比例、构图、材质、照明、道路可读性和接缝视觉达到可继续精修的地编基线；该审阅由用户验收，不由自动测试代替。

## Out of Scope

- 将新地图挂到 `godot/client/scenes/main.tscn` 或替换产品主场景。
- 接入现有车辆、Jolt、挖斗切削、土量守恒、倾倒或持久化链路。
- Windows/Linux 发行包、导出模板和产品安装包。
- 全素材库导入、系统性减面、重新 UV、纹理烘焙、LOD/HLOD 或最终移动端预算。
- 沿用、修补或迁移现有产品施工区布局。
