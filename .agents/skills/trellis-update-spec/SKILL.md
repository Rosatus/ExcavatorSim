# Update knowledge
Update specs for durable contract changes or supported non-obvious lessons. No mandatory retrospective after every task.
Read the target and replace stale text. Include trigger, contract, reason and useful code/test references; add signatures/cases/matrices only when helpful. No fixed seven-section template.
Concrete contracts belong in layer specs; reusable questions in short guides; progress/evidence in task records. Tests/code may sufficiently document obvious behavior.
Do not invent universal rules from one incident, require code examples for prose corrections, sync nonexistent upstream templates or automatically commit. A no-op needs no report unless asked.
