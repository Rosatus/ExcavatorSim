# Requirements and rolling planning
Follow workflow step 1.1; no separate approval gate.
Inspect available facts first. Ask only unresolved choices affecting scope, visible behavior, compatibility, acceptance or irreversible impact. Explain recommendation/consequences; group independent questions and continue unrelated work.
For tracked work record requirements/non-goals and observable acceptance in `prd.md`. Preserve source constraints/decisions without copying whole conversations. Discussion or user opt-out requires no task file.
Define large-task milestones, dependencies and final integration acceptance. Detail only the next ready milestone. Future milestones can retain unknowns and resolution triggers. Parent/child tasks are for independent deliverables, not a requirement to plan all children before starting.
Use `implement.md` for rolling steps/checkpoints and `design.md` for substantial architecture choices when useful. No file quota or mandatory whole-PRD rewrite. Keep facts authoritative in one place.
When current scope/acceptance/blockers are understood and implementation authorized, summarize and proceed. Wait only for explicit plan review or a material unresolved decision. Technical refinements within scope need no reapproval.
